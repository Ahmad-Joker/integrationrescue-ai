# Judge Q&A (draft)

**Is this real AI or a script?** Two decision makers share one tool interface. Live mode uses Gemini (function calling) or
Claude (tool use); the demo shown may be the deterministic baseline and is labelled so. Tool execution, sandboxing and
verification are identical in every mode. Live results are only the ones recorded in `docs/EVALUATION_PLAN.md`.

**What stops the agent from "fixing" by cheating?** It can't edit tests, the verifier, or anything outside two allow-listed
paths; the regression test is generated by our code and must fail before the patch; the verifier reads the database
read-only and derives the expected plan from billing. A patch granting Pro to everyone is caught by the existing suite (tested).

**What about prompt injection in tickets?** Ticket/log/API content is data; tools are typed and phase-gated; tested with a
ticket that orders the agent to read `.env` and mark itself verified.

**Duplicate charges?** Payments are idempotent; replay redelivers the stored event and never charges; the verifier asserts
exactly one successful charge and one grant; tested with duplicate-delivery and lost-ack faults.

**Isn't this what Datadog / Sentry / coding agents do?** They diagnose telemetry or fix code. Our narrow claim is verifying the
cross-system business outcome independently of the AI. We plan a head-to-head against a coding agent with the same verifier.

**Customers?** None yet. This is a prototype on simulated services with fictional data.
